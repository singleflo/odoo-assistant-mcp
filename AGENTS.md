# AGENTS.md — odoo-assistant-mcp

MCP server (`odoo-assistant` on PyPI, stdio transport) wrapping 9 battle-tested
Odoo scripts as MCP tools. **Current state: pre-M0 scaffolding** — no
`pyproject.toml`, no `server.py`, no git repo yet, `tests/` empty. The plan is

## Hard rules

- **Never rewrite `src/odoo_assistant/odoo_scripts/`.** Those 9 scripts are verified against a live instance and are the source of truth; the MCP server is a ~200-line thin wrapper importing them. Canonical copy lives at `~/.agents/skills/odoo/` — sync direction is skill → this repo.
- Scripts are **flat modules**: each does `sys.path.insert(0, <own dir>)` + `from odoo_client import ...`. Keep that import style working when packaging.
- SDK API: `from mcp.server import FastMCP` — **`MCPServer` does not exist** (parts of `docs/mcp-server-guide.md` describe a future SDK 2.0; IMPLEMENTATION-REVIEW GAP 1 is the correction). Pin `mcp>=1.28.1,<2`.
- stdio transport: **nothing may print to stdout** except the JSON-RPC stream. Diagnostics → stderr.
- Every write tool goes through the safety layer (`classify()` → L0–L5). L4/L5 refuse by default; `ODOO_MCP_MAX_LEVEL` moves the bar. Host consent dialogs are untrusted — the safety layer is the only enforcement point.

## Odoo landmines (silent wrong results, not errors)

Full list: `references/SKILL.md` (8 rules) + `references/writing.md` (12 patterns). The ones that bite code:

- Odoo commits **before** serializing the XML-RPC response: an exception can mean "committed but unserializable" (`OdooExecutedButUnserializable`). **Never retry on exception** — re-read the record instead. Blind retries created duplicate invoices.
- A returned dict with `res_model` is a wizard to follow, not a result.
- `account.move` / `account.move.line` without a `move_type` filter mixes invoices, bills and journal entries (3.613 vs 373). The safety layer blocks this structurally.
- Sum `*_signed` fields, never `amount_total` (multi-currency inflated a total 11,9×).
- Multi-company: pass `context={"allowed_company_ids": [...]}` or you report one company's figures as the whole business.
- Wrong `ODOO_USER` makes `authenticate()` return `False`, not raise — looks like a permission error.
- `create()` returns a list, not an int. Methods starting with `_` are always rejected — use the public wizard.
- Idempotency: `Writer.create(..., unique_on=[...])`, chains via `Writer.step()`; a write is done only when a re-read proves it.

## Live testing

- Env vars: `ODOO_BASE_URL` (no trailing slash), `ODOO_API_KEY` (never a password); `ODOO_DB`/`ODOO_USER` required for the XML-RPC transport. No credential defaults, by design.
- Reference dev instance: `persevida_dev18` (Odoo 18 Enterprise, 2 companies ES/CZ, destructive tests allowed; JSON-2 absent → transport is XML-RPC). Sanity figures in `references/BUILD-STATE.md`.
- `odoo_client.py` hard-blocks `PRODUCTION_HOSTS` (`app.persevida.com`).
- Smoke-test the scripts directly: `python3 src/odoo_assistant/odoo_scripts/query.py --url http://host:8069 --key <API_KEY>`
